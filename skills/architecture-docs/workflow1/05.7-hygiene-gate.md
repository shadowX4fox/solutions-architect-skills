#### Step 5.7: Content Hygiene Gate (BLOCKING — runs before Step 6)

After Step 5 completes (all `docs/` files written), run the Content Hygiene Gate. The gate is BLOCKING — Step 6 (ADR delegation) does NOT run until it passes.

**Five checks, one pass over the `docs/` files** (they are already in context from Step 5):

| # | Check | Source of rules |
|---|---|---|
| 0 | Section-file completeness | this step, below |
| 1 | Placeholder elimination | `[plugin_dir]/skills/architecture-docs/PRINCIPLE_VALIDATION.md` § Appendix A — Mandatory-Field Placeholder Map |
| 2 | Anchor presence | this step, below |
| 2b | EXPLORER_HEADER contract | `bun [plugin_dir]/skills/architecture-explorer-headers/utils/explorer-cli.ts check <project_root>` — exit 1 is a FAIL |
| 3 | Prose style | `bun [plugin_dir]/skills/architecture-docs/scripts/prose-check.js <project_root> --scope first-write` — `PROSE_VALIDATION.md` as code |
| 4 | Size budgets (shape budgets BLOCKING when stamped; byte budgets WARNING) | `scripts/docs-stats.js` — `ARCHITECTURE_DOCUMENTATION_GUIDE.md` → "Authoring budgets" |

A banned construction is a FAIL on the same terms as a placeholder. A length or form warning is
not — see check 3.

---

**Check 0 — Section-file completeness.** Runs first, because checks 1–3 inspect files that must
exist before they can be inspected. Every section file in the canonical layout must be present:

```bash
for f in 01-system-overview 02-architecture-principles 03-architecture-layers \
         04-data-flow-patterns 05-integration-points 06-technology-stack \
         07-security-architecture 08-scalability-and-performance \
         09-operational-considerations 10-risks-and-technical-debt 11-references; do
  [ -f "docs/$f.md" ] || echo "MISSING: docs/$f.md"
done
[ -f docs/components/README.md ] || echo "MISSING: docs/components/README.md"
```

Any `MISSING:` line is a **FAIL**. Create the file from its template — Section 13's is in
`ARCHITECTURE_DOCUMENTATION_GUIDE.md` → "Section 13: Risks and Technical Debt" — and re-run the
gate from check 0. `docs/components/README.md` is the one exception to "create it here": delegate
to `architecture-component-guardian`, which is its only sanctioned writer.

The check is a literal file-presence test rather than a review of Step 5's output, because the
failure it exists to catch is **omission**, and omission is exactly what a reviewer reading the
files that *were* written cannot see. `docs/10-risks-and-technical-debt.md` shipped missing from
every architecture this workflow created until v5.0.0 — Step 5's creation order simply skipped it,
and nothing downstream noticed, because Workflow 11's legacy-layout detector requires
`docs/10-references.md` to exist and fresh creation never produces that file. A gate that asks
"is what you wrote correct?" would have passed every one of those runs.

**Mandatory-field map** lives in `[plugin_dir]/skills/architecture-docs/PRINCIPLE_VALIDATION.md` § Appendix A — Mandatory-Field Placeholder Map (the list below is that map; open the file only if it disagrees). Scope `first-write` enforces:

- `docs/01-system-overview.md`: System Name, Purpose, Business Value, every Key Metric row
- `docs/02-architecture-principles.md`: every Description / Implementation / Trade-offs subsection (also enforced by the Section 3 Enforcement Gate)
- `docs/03-architecture-layers.md`: `<!-- ARCHITECTURE_TYPE: -->` value, every layer name and description
- `docs/06-technology-stack.md`: Languages, Frameworks, Databases, Infrastructure tables
- `docs/07-security-architecture.md`: Authentication, Authorization, Encryption-in-transit, Encryption-at-rest
- `docs/components/<system>/NN-*.md`: Type, Technology, C4 Level, Description (the canonical name first, ≤ 120 characters — `component-cli.ts check` holds it), Purpose
- `docs/components/<system>.md`: Owner, Containers count, Description

**Detection** — the token list is language-aware (`references/LANGUAGE_POLICY.md` §5.6). Run it regardless of `doc_language`; a mixed-language document is itself a defect worth catching:

```bash
rg -ni '\[(to be defined|tbd|placeholder|fixme|your [a-z]+|describe [a-z]+|por definir|pendiente|marcador|describa [a-zá-ú]+|su [a-zá-ú]+)\]|<TODO>|TODO:|XXX' \
  docs/01-system-overview.md docs/02-architecture-principles.md docs/03-architecture-layers.md \
  docs/06-technology-stack.md docs/07-security-architecture.md docs/components/ \
  | rg -v -F '<!-- TODO: Add source reference -->'
```

The source-reference marker `<!-- TODO: Add source reference -->` is **not** a placeholder: Step 5 writes it where the payload had no fact (`05-sections.md` step 2, the guide's *Unverifiable Claims*), beside the literal `Not documented`. The filter above drops those lines; count them (`rg -c -F '<!-- TODO: Add source reference -->' docs/`) and report the count as open sourcing work — it never fails the check (8.102.0; in the 2026-09-30 control runs the unfiltered regex failed the gate on every Key Metric the PO Spec did not state, and one run needed a second sub-agent to clear it).

**Anchor-presence check** (runs in the same pass, both languages). Every structural heading written by Step 5 must carry its English anchor comment, or downstream gates lose their match target:

```bash
# every numbered H2 in a section file must end with a SECTION anchor
rg -n '^## [0-9]+\. ' docs/*.md | rg -v '<!-- SECTION: ' || echo "OK: all numbered sections anchored"
# every principle H3 must end with a PRINCIPLE anchor
rg -n '^### [0-9]+\. ' docs/02-architecture-principles.md | rg -v '<!-- PRINCIPLE: ' || echo "OK: all principles anchored"
```

A heading missing its anchor is a **FAIL** on the same terms as a placeholder — regenerate the heading with the anchor and re-run.

**Check 2b — EXPLORER_HEADER contract.** Run `bun [plugin_dir]/skills/architecture-explorer-headers/utils/explorer-cli.ts check <project_root>` and quote its output. It holds every `docs/NN-*.md` and `docs/components/**/*.md` to the contract the explorer CLI, the component facts, the dossier and the backfill skill all read through one parser: a header right after the H1, one block, only the closed key set (a translated or invented key is dropped silently by the parser — the check names it), the required fields, `component_self` equal to the file's slug, `components` and `related_adrs` that exist on disk. **Any error is a FAIL**: fix the header and re-run the check. Warnings (a `scope` over 120 characters, a missing 30-second summary) are reported and do not block.

**Check 3 — Prose style.** Run `bun [plugin_dir]/skills/architecture-docs/scripts/prose-check.js <project_root> --scope first-write` and quote its `PROSE_VALIDATION_REPORT` line and findings. The script is `PROSE_VALIDATION.md` as code — every rule, both language branches, the mode from the marker; nothing is transcribed and nothing is self-attested. Exit 1 is a FAIL.

- **BLOCKING** (Groups 1, 2): template boilerplate residue, filler openers, meta-narration, hedges, marketing register, first/second person. Literal strings — the proper-noun guard reads the ledger (`Robusta` is a technology, not *robust*).
- **WARNING** (Groups 3–7): sentence and paragraph length, form, density, voice, waiver accounting. Surface them in the summary and **proceed** — do not loop on warnings.
- **The judgement rules go to the judge, and this gate answers them** (8.119.1). `S-DENSITY-01`, `S-DENSITY-02`, `S-VOICE-02`, `S-VOICE-03`, `S-HIST-01` and the Spanish pro-drop check are one question per regex candidate through `scripts/judge.js`. Under the default `agent` engine the first run writes a worksheet per rule under `.cache/sa-skills/judge/` and lists every candidate as **undecided** — no regex reading stands in (8.119.0), so a PASS with undecided candidates is not a pass yet. For each worksheet the report names, dispatch the `sa-skills:reviewers:worksheet-judge` subagent (Haiku) once per worksheet, several in one message — it writes the answers file the worksheet names under its fingerprint (a `segment-runner`, which cannot dispatch, answers them itself) — then re-run the same `prose-check.js` command: it applies the answers, keeps or dismisses each candidate and prints every dismissal. Under `SA_JUDGE=typesafe` or `clef` nothing is pending. A kept candidate is handled like any other finding of its rule.
- If `<!-- PROSE_STYLE: v1 -->` is absent from `ARCHITECTURE.md`, the script runs in `mode: report-only`: every finding is a WARNING, nothing blocks, exit 0. On a passing enforcing run, stamp the marker.
- Read `PROSE_VALIDATION.md` only for the fix text of a rule the report names.

There is **no file-length rule** in this gate and there must never be one — see `references/PROSE_STYLE.md` § "No file-length cap".

**Check 4 — Size budgets.** Run `bun [plugin_dir]/skills/architecture-docs/scripts/docs-stats.js <project_root>` and print its table and findings verbatim. The **shape budgets** (principle, risk-register cell, integration block, component descriptor) are BLOCKING once `<!-- PROSE_STYLE: v1 -->` is stamped — their fix is to move the argument to the ADR or document it cites, never to drop the fact; the **byte budgets** of a section file stay WARNING (there is no file-length cap). A finding is information for the architect — a principle over its bullet budget, a per-phase sequence diagram, a risk row that argues instead of linking, an ADR index restated in `docs/11`, a component descriptor over 10 KB, a component described outside its file. Fix what is cheap to fix now (a restated ADR index, an unjustified per-phase diagram); leave the rest with the report. Never drop a fact to satisfy a budget.

**Check 5 — Code identifiers in English (WARNING).** Run `bun [plugin_dir]/scripts/shared/identifier-check.js <project_root>` and quote its `IDENTIFIER_CHECK` line and findings. Under any `DOC_LANGUAGE` an API path, field, schema, enum value, topic, table or key prefix in a code span is English (`LANGUAGE_POLICY.md` §4) — the handoff assets copy it verbatim. On `PENDING` the session is the judge: answer the worksheet the note names (one `1` / `0` per item — is this identifier Spanish?) into the answers file it names, then re-run the same command (it applies them; `--answers` does the same explicitly); under `SA_JUDGE=typesafe` or `clef` the model answers in the same run and nothing is pending. Fix a finding by renaming the identifier in the document (the prose stays in the document language); a data value an ADR defines keeps its ADR's form. Never blocks.

---

**Pass criterion**: 0 missing section files, 0 placeholder matches in the listed mandatory fields, 0 unanchored structural headings, 0 EXPLORER_HEADER errors, and 0 BLOCKING prose findings. Byte-budget findings never fail the gate; a shape-budget finding does once the project is stamped. Matches in non-mandatory fields and all prose WARNINGs are warnings, not blockers.

**Check 0 has no override.** The round-4 escalation below lets the user accept a document with placeholders intact; it does not let them accept a document with a section file missing. A placeholder is visible to whoever opens the file, so accepting one is an informed choice. An absent file is invisible — it degrades silently into "this architecture has no technical debt" three skills downstream. Create the file, then escalate on its contents if needed.

**On PASS**: `create-progress.js <project_root> --done 5.7`, then Step 6. A gate with a judge worksheet still pending (Check 3 or Check 5 reporting undecided / `PENDING`) has not passed: hand it to the worksheet-judge subagent and re-run that check first (8.119.1 — on the 2026-10-02 control run the gate was marked with four worksheets pending, and they were answered by hand after the run, reopening Section 3).

**On FAIL**: list every offending field to the user with the file:line reference, regenerate the offending field with concrete content, re-run the gate. Cap at 3 rounds. Round 4 → escalate to user with the list and ask whether to proceed with the placeholders intact (explicit override only).

**Why this gate**: an architecture document that ships with `[To be defined]` / `[Por definir]` in mandatory fields will silently fail compliance contracts and the release workflow downstream. An unanchored heading fails the same way, and more quietly — the Section 6 mode detector and the compliance validators simply stop finding the section. Template boilerplate is the third species of the same defect: a sentence like "This section provides a visual representation…" is authoring instruction that leaked into a deliverable, and it survives every other check because it is grammatically perfect. Catching all three here costs minutes; catching them at release costs days.
